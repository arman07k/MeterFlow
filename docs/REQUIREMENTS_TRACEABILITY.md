# MeterFlow Requirements Traceability Matrix (`docs/REQUIREMENTS_TRACEABILITY.md`)

## 1. Purpose & Status Definitions

This document provides individual, bidirectional traceability across **Functional Requirements (`FR1`–`FR10`)**, **Quality Attribute Requirements (`QA1`–`QA5`)**, and **Common Engineering Requirements (`C1`–`C12`)** (`C4`).

### Canonical Status Definitions

- **`Implemented and verified`**: Implemented on disk and validated end-to-end by automated unit, integration, security, UI, or full-scale benchmark tests with factual evidence.
- **`Implemented but partially verified`**: Implemented on disk and verified locally via automated tests, while one specific external/environment aspect (such as host `k6` CLI execution, live Supabase connection, or HTTP Basic BCrypt `p95 <= 100 ms` under 1,000-event max batches) remains environment-bounded or documented honestly.
- **`Not verified`** / **`Not implemented`**: Reserved for unverified or unbuilt items.
