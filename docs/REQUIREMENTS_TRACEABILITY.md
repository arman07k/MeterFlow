# MeterFlow Requirements Traceability Matrix (`docs/REQUIREMENTS_TRACEABILITY.md`)

## 1. Source of Truth, Missing Instructor Files & Status Definitions

This document provides individual, bidirectional traceability across **Functional Requirements (`FR1`–`FR10`)**, **Quality Attribute Requirements (`QA1`–`QA5`)**, and **Common Engineering Requirements (`C1`–`C12`)** (`C4`).

> **Important Scope Notice (Missing Instructor Handout / Rubric):** No original external instructor specification file (such as an assignment PDF, DOCX handout, grading rubric, or course/team roster) is present inside this repository. Accordingly, every requirement ID and acceptance target below is traced strictly against the repository's documented project specifications ([`docs/PROJECT_CHARTER.md`](./PROJECT_CHARTER.md), [`docs/architecture/QUALITY_ATTRIBUTE_PLAN.md`](./architecture/QUALITY_ATTRIBUTE_PLAN.md), [`docs/architecture/UTILITY_TREE.md`](./architecture/UTILITY_TREE.md), and `ADR-001`–`ADR-015`), the actual implemented code and PostgreSQL schema (`V1`–`V8`), and verified automated test and benchmark evidence. No unverified instructor requirements have been assumed or invented.

### Truthful Verification Status Definitions

- **`Verified`**: Implemented in the codebase and independently verified end-to-end by automated unit, security, architecture, UI, or PostgreSQL 17 Testcontainers integration tests with factual evidence.
- **`Partially verified`**: Core implementation exists and is verified by automated tests, while one or more documented scope items, environmental checks, or target SLIs remain unexecuted, environment-bounded, or unimplemented (explained explicitly in each row).
- **`Implemented but not independently verified`**: Implemented on disk, with no independent automated execution verifying the runtime behavior.
- **`Not implemented`**: Not present in the repository.
- **`Not applicable`**: Outside the applicable system scope.
